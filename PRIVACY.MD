# Политика конфиденциальности Astra — Древо Щит

**Последнее обновление:** 22.11.2026 (версия 0.7.2)

**Astra — Древо Щит** (далее — «Расширение», авторы: Александр Емельянов, Никита Емельянов) разработано с приоритетом конфиденциальности пользователей и минимальной обработки данных.

## 1. Сбор и передача персональных данных
Расширение **не собирает, не хранит на удалённых серверах, не продаёт и не передаёт третьим лицам** персональные данные пользователей, историю посещений, поисковые запросы, содержимое веб-страниц, пароли или платёжную информацию. У Расширения отсутствует собственный сервер телеметрии или аналитики.

## 2. Локальное хранение данных (`chrome.storage.local` / `sync` / `session`)
Все настройки, индивидуальные переопределения модулей для отдельных сайтов (`siteOverrides`), пользовательские правила блокировки (CSS-селекторы, чёрный и белый списки доменов), кэш фильтров, локальный реестр SHA-256 хэшей угроз, статистика сэкономленного трафика и счётчики заблокированных угроз хранятся **исключительно локально на устройстве пользователя** в хранилище браузера (разрешения `storage` и `unlimitedStorage`). Пользователь может в любой момент экспортировать, импортировать или полностью удалить эти данные в настройках Расширения.

## 3. Использование разрешений браузера
- **`webRequest`, `declarativeNetRequest` и `declarativeNetRequestFeedback`:** используются исключительно локально в браузере для блокировки рекламы, трекеров, криптомайнеров и подсчёта сэкономленного трафика на текущей вкладке. Сетевой трафик не перенаправляется на сторонние прокси-серверы и не записывается в историю.
- **`tabs`, `webNavigation` и `scripting`:** применяются локально для проверки текущего открытого домена на признаки фишинга и кликджекинга, внедрения защитных скриптов (включая опциональную защиту от фингерпринтинга и утечек локального IP через WebRTC) и отображения статуса безопасности на иконке Расширения.
- **`contextMenus`:** используется для добавления пункта «Заблокировать элемент (Astra)» в контекстное меню страницы при ручном выборе рекламных блоков пользователем.
- **`downloads` и `notifications`:** используются локально для предупреждения или блокировки скачивания потенциально опасных файлов и уведомления пользователя об угрозах. Расширение не отправляет имена скачиваемых файлов, пути или метаданные на внешние серверы.
- **`alarms`:** применяется для периодического фонового обновления публичных списков фильтрации и репутации.

## 4. Взаимодействие со сторонними открытыми источниками
Для поддержания актуальности баз защиты Расширение выполняет прямые обезличенные HTTP-запросы без передачи идентификаторов пользователя к следующим источникам:
- **Списки фильтрации рекламы и трекеров** (`EasyList`, `RuAdList`, `EasyPrivacy`, `Peter Lowe` через официальные зеркала `easylist.to`, `adblockplus.org`, `jsdelivr.net`, `://githubusercontent.com`, `pgl.yoyo.org`) — для локального обновления правил блокировки.
- **Открытые базы фишинговых угроз** — для локальной проверки репутации доменов.
- **Протокол RDAP (`rdap.org`)** — для проверки даты регистрации незнакомых зарубежных доменов при подозрении на фишинг. При обращении передаётся только имя проверяемого домена.
- **Опциональный эндпоинт агрегатора SHA-256 хэшей** (настраивается пользователем вручную в разделе «Базы и Репутация») — при указании URL выполняется только обезличенный GET-запрос для загрузки списка хэшей вредоносных файлов без передачи каких-либо данных пользователя.

## 5. Изменения в Политике конфиденциальности
При добавлении новых функций в Расширение настоящая Политика может обновляться. Актуальная версия всегда публикуется на странице Расширения в каталоге дополнений и в репозитории проекта.
